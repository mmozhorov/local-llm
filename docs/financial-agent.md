# Финансовый агент: best practices для пошагового анализа компании

Документ собирает практики проектирования LLM-агента, который проводит **комплексный анализ публичной компании** — фундаментальный, технический и сентимент-блок — в виде дисциплинированного, проверяемого, пошагового процесса.

Методологическая основа — workflow **Superpowers** (плагин для Claude Code от Jesse Vincent, `obra/superpowers`): brainstorming → spec → plan → execute, с жёсткими гейтами между фазами, явными чек-листами и сохранением артефактов на диск. В программировании этот подход вытесняет «вайб-кодинг» и резко сокращает дорогие ошибки; в инвест-анализе он играет ту же роль — вытесняет «вайб-инвестинг» (купил, потому что нравится).

> **Главная идея.** Финансовый анализ — это не одна большая задача, а конвейер из 6–7 коротких фаз, каждая со своим входом, выходом, чек-листом и контрольным вопросом «всё сходится?». Между фазами стоят гейты: пока артефакт предыдущей не сохранён и не подтверждён, агент не идёт дальше и тем более не делает финальный вывод.

---

## 1. Философия и принципы

Эти принципы — прямой перенос из `superpowers/SKILL.md`, адаптированный под инвест-анализ.

### 1.1 Hard-Gate — никаких выводов до прохождения всех фаз

> **HARD-GATE.** Агент НЕ выдаёт итоговый тезис («покупать / держать / продавать», целевую цену, рейтинг) пока не пройдены все обязательные фазы и не сохранены их артефакты. Это правило действует для ЛЮБОЙ компании — даже «очевидной».

Анти-паттерн: *«Это же [Apple / Сбербанк / NVIDIA], тут и так всё ясно».* Именно на «очевидных» кейсах непроверенные допущения дороже всего стоят.

### 1.2 Один вопрос за раз

Когда требуется уточнение у пользователя — **один вопрос в одном сообщении**, желательно с вариантами ответа. Не нужно «допрашивать»: горизонт, риск-аппетит, валюта, бенчмарк — это разные сообщения. Это снижает когнитивную нагрузку и резко повышает качество ответов.

### 1.3 Альтернативы перед решением

Перед любым выводом — **2–3 альтернативные интерпретации с трейд-оффами**:

- бычий сценарий, медвежий, базовый — обязательно все три;
- при оценке: DCF, мультипликаторы peers, EV/EBITDA — минимум два независимых метода, расхождение объясняется явно;
- при технике: «трендовая интерпретация vs боковик», «прорыв vs ложный пробой».

### 1.4 Инкрементальная валидация (sections with checkpoints)

Длинный анализ выкладывается секциями, **после каждой секции** — короткая фиксация: что выяснили, что осталось открытым, переходим ли к следующей фазе. Это эквивалент «present design in sections, ask after each whether it looks right» из brainstorming-скилла.

### 1.5 YAGNI и ruthless scope

Не нужно тащить в анализ метрику только потому, что она «есть в учебнике». Для софт-компании EV/EBITDA и unit economics > P/B. Для банка — наоборот, P/B и NIM ключевые, EV/EBITDA не используется (банки → EBITDA не имеет смысла). Скоуп определяется бизнес-моделью, а не шаблоном.

### 1.6 Evidence over claims

Каждое утверждение — со ссылкой на источник (отчёт МСФО, 10-K, скриншот графика, новость с датой). Если ссылки нет — это не вывод, а гипотеза, и она помечается как `[hypothesis]`.

### 1.7 Root-cause, а не симптомы

Если метрика «странная» (резкий скачок маржи, провал FCF) — копать до причины: разовый эффект, изменение учётной политики, M&A, валютная переоценка. Симптоматическое объяснение («ну выросло») запрещено.

### 1.8 Письменные артефакты

Каждая фаза оставляет файл на диске (или секцию в одном markdown-файле). Это даёт:

- **resumability** — можно вернуться через неделю и продолжить;
- **reviewability** — пользователь или другой агент видит, что было сделано;
- **correctability** — если на фазе 4 нашлась ошибка фазы 2, её правят локально, не переделывая всё.

## 2. Архитектура агента (superpowers-style skills)

Структура повторяет `obra/superpowers/skills/*`: каждая фаза — отдельный `SKILL.md` с frontmatter, чек-листом и process flow.

```
.claude/skills/financial-analysis/
├── SKILL.md                          # корневой роутер: skill-first protocol
├── 00-scoping/SKILL.md               # уточнение цели, горизонта, риск-профиля
├── 01-company-context/SKILL.md       # бизнес-модель, сектор, география
├── 02-fundamental/SKILL.md           # МСФО/GAAP, мультипликаторы, DCF
├── 03-technical/SKILL.md             # цена, объёмы, индикаторы, паттерны
├── 04-sentiment-macro/SKILL.md       # новости, инсайдеры, макро, регуляторика
├── 05-synthesis/SKILL.md             # bull/bear/base, риски, чувствительность
├── 06-verdict/SKILL.md               # тезис, target price, position sizing
└── shared/
    ├── data-sources.md               # каталог API/источников
    ├── anti-patterns.md              # типовые ошибки и как их ловить
    └── templates/                    # шаблоны artifacts
        ├── company-onepager.md
        ├── dcf-worksheet.md
        ├── ta-checklist.md
        └── final-thesis.md
```

В системный промпт агента кладётся **skill-first protocol**:

> Перед любым шагом агент проверяет: есть ли подходящий skill в `.claude/skills/financial-analysis/`. Если есть — следует его инструкциям буквально. Самодеятельность вне скилла запрещена.

Артефакты складываются в `docs/research/<TICKER>/YYYY-MM-DD/` — по аналогии с `docs/superpowers/specs/`.

## 3. Фазовый workflow

Семь фаз с явными гейтами. Каждая — мини-skill.

### Фаза 0. Scoping (аналог brainstorming)

**Триггер:** пользователь произнёс тикер или название компании.

**Цель:** не начинать анализ, пока не понятны:

| Параметр | Зачем |
|---|---|
| Горизонт инвестирования | Дневной трейдинг vs 10-летний buy-and-hold — это два разных анализа |
| Валюта учёта | USD/RUB/EUR — определяет валютные риски и сравнения |
| Бенчмарк | S&P 500, MOEX, сектор — без него Sharpe/alpha не считаются |
| Риск-профиль | Допустимая просадка, размер позиции |
| Цель работы | Принятие решения / due diligence / academic exercise / собес |
| Известные позиции | Уже в портфеле / шорт / опционы — влияет на anchoring bias |

**Правило:** один вопрос за раз, multiple-choice предпочтительнее, ждать ответа. Если пользователь явно отказывается уточнять — фиксировать дефолты явно: *«принимаю горизонт = 1 год, базовая валюта = USD, бенчмарк = S&P 500, без открытых позиций. Подтвердите.»*

**Артефакт:** `docs/research/<TICKER>/YYYY-MM-DD/00-scope.md` с явным TL;DR в 5 строк.

**Гейт:** scope подтверждён пользователем → переход к Фазе 1. Иначе — повторный цикл вопросов.

---

### Фаза 1. Company context

**Цель:** агент понимает, ЧТО за компания, до того как считать любые цифры.

Чек-лист:

- [ ] **Бизнес-модель в одном абзаце:** что продаёт, кому, как зарабатывает, чем платит за рост.
- [ ] **Сегменты выручки** с долями (по последнему годовому отчёту) и темпами роста по каждому.
- [ ] **География выручки** в долях; экспортная зависимость, валютные риски.
- [ ] **Цепочка создания стоимости:** где компания находится — добыча/переработка/дистрибуция/розница/IP.
- [ ] **Конкурентный ров (moat):** один из 5 типов по Porter / Morningstar — network effects, switching costs, cost advantage, intangibles, efficient scale. Если ни одного — пометить.
- [ ] **Топ-5 конкурентов** (peer set) для дальнейших сравнений.
- [ ] **Регуляторное окружение:** санкции, антимонополька, лицензии, ESG-риски.
- [ ] **Структура собственности:** контролирующий акционер, free float, инсайдерская доля.
- [ ] **Стадия жизненного цикла** компании: growth / mature / cyclical / turnaround — определяет, какие метрики ключевые.

**Анти-паттерн:** «Apple — это техкомпания». Слишком общё. Корректно: *«Apple — вертикально интегрированная экосистема премиум потребительской электроники + растущий сервисный бизнес (~25% выручки, маржа ~70%), доля сервисов растёт как обещание де-рискования аппаратного цикла»*.

**Артефакт:** `01-context.md` (one-pager, до 1 страницы).

**Гейт:** есть ответ на «почему эта компания вообще существует и кто её клиент» → Фаза 2.

### Фаза 2. Fundamental analysis

Делится на пять подсекций: **качество отчётности → P&L → баланс → cash flow → оценка**.

#### 2.1 Quality of earnings

Сначала проверка, что цифрам можно верить:

- [ ] Аудитор и есть ли оговорки (qualified opinion).
- [ ] Расхождение GAAP/IFRS vs non-GAAP (adjusted) — если adjusted EBITDA выше GAAP больше чем на 15–20%, копать что исключили.
- [ ] Накопленный gap между Net Income и Operating Cash Flow за 5 лет (если NI растёт, а OCF — нет, это красный флаг earnings quality).
- [ ] Beneish M-Score / Sloan accruals — формальные индикаторы манипуляций.
- [ ] Going concern / event after reporting period в примечаниях.

#### 2.2 P&L (5 лет минимум, желательно 10)

| Метрика | На что смотрим |
|---|---|
| Revenue CAGR | органический vs M&A; темп vs рынок |
| Gross margin | устойчивость, тренд |
| Operating margin | операционный леверидж |
| Net margin | налоговая ставка, разовые события |
| EPS | разводнение акциями vs buyback |
| ROIC, ROE | основной KPI качества бизнеса; ROIC > WACC обязательно для созидания стоимости |

Сравнение **в трёх измерениях**: исторически (тренд), с peers, с собственным менеджмент-гайденсом.

#### 2.3 Balance sheet

- [ ] Net Debt / EBITDA — leverage; для нециклички обычно < 3×, для коммодити < 1.5×.
- [ ] Interest coverage (EBIT / interest) — > 5× здоровая, < 2× проблемная.
- [ ] Current / Quick ratio — ликвидность.
- [ ] Working capital cycle (DSO + DIO − DPO) — управление оборотным капиталом.
- [ ] Goodwill / Total assets — риск списания, особенно после M&A.
- [ ] Off-balance: операционная аренда (IFRS 16 уже на балансе, но смотрим контракты), pension liabilities, гарантии.

#### 2.4 Cash flow

- [ ] OCF / Net Income > 1.0 устойчиво — признак реальных денег.
- [ ] **FCF = OCF − capex** (классический), **FCFE** — для оценки equity holder.
- [ ] Capex breakdown: maintenance vs growth (если компания не раскрывает — оценить по амортизации как нижней границе maintenance).
- [ ] Доля FCF, идущая на дивиденды + buyback (payout) и на M&A.
- [ ] **Cash conversion = FCF / Net Income** — идеально 80–100%+.

#### 2.5 Valuation

Минимум **два независимых метода**, расхождение объясняется.

**Multiples (relative):**

- Подобрать peer set из Фазы 1 (5–8 компаний, сопоставимая бизнес-модель, география, размер).
- Для каждой посчитать **trailing и forward** мультипликаторы: P/E, EV/EBITDA, EV/Sales, P/B (для банков и страховщиков), EV/FCF.
- Сравнить медиану peers и текущую компанию; разница > 25% — объяснить (премия за качество, дисконт за риск).
- Историческая премия/дисконт к own 5y average.

**DCF (intrinsic):**

- Горизонт явного прогноза 5–10 лет, terminal value через Gordon growth (g обычно 1–3% в реальных).
- WACC: cost of equity по CAPM (Rf + β·ERP), cost of debt после налогов, по рыночным весам.
- **Сценарии**: base, bull, bear с разными g, маржей, capex. Sensitivity table по WACC vs terminal g — обязательна.
- Discount: проверить, что PV(terminal value) не > 75% от EV; если > — модель «всё в терминале», ненадёжна.

**Sum-of-the-Parts** — если конгломерат или сегменты с радикально разной экономикой.

**Артефакты:** `02-fundamental.md` + `02-dcf.xlsx` (или markdown-таблица).

**Гейт:** есть **fair value range** (например, «$140–$180 за акцию, центральная $160») с указанием метода и допущений → Фаза 3.

### Фаза 3. Technical analysis

TA — это не «гадание по графикам», а структурированный взгляд на **цену, объём и тайминг**. Подход «top-down»: индекс → сектор → бумага → таймфрейм решения.

#### 3.1 Multi-timeframe map

Три экрана (правило Эльдера):

1. **Старший таймфрейм (W/M):** тренд. Если на месяце нисходящий — long-only стратегии откладываются.
2. **Средний (D):** сигналы входа/выхода.
3. **Младший (H4/H1):** тонкая настройка точки входа.

#### 3.2 Базовый чек-лист

- [ ] **Trend:** higher highs + higher lows = uptrend. Простая EMA(20)/EMA(50)/EMA(200) сверху вниз для uptrend.
- [ ] **Поддержка / сопротивление:** свежие 2–3 уровня, видимые на скриншоте.
- [ ] **Объём:** растущий тренд на росте объёма; дивергенция объёма (цена выше, объём падает) — предупреждение.
- [ ] **Momentum:** RSI(14), MACD. Перекупленность > 70 / перепроданность < 30 — не сигнал к развороту сами по себе, только в контексте.
- [ ] **Волатильность:** ATR(14) — для расчёта стоп-лосса (обычно 1.5–3 ATR от точки входа).
- [ ] **Bollinger bands / Keltner** — сжатие предсказывает выход импульса.
- [ ] **Свечные паттерны разворота** на ключевых уровнях: pin bar, engulfing, evening/morning star.
- [ ] **Графические паттерны:** треугольники, флаги, head & shoulders, double top/bottom — с явным указанием цели и инвалидации.
- [ ] **Дивергенции RSI/MACD vs цена** — особенно на старшем таймфрейме.

#### 3.3 Контекст рынка

- [ ] Тренд индекса (S&P 500, MOEX) — long в бумаге против медвежьего рынка имеет 2× меньше шансов.
- [ ] Тренд сектора (XLK, XLF и т.п.).
- [ ] Relative strength: RS vs benchmark — рост быстрее индекса = лидер.
- [ ] Корреляция и β.

#### 3.4 Уровни входа, цели и стопов

Без чисел TA бесполезен:

- **Entry:** конкретный диапазон цен, например «$148–$152 при касании EMA50 + bullish engulfing».
- **Stop-loss:** ниже структурного уровня, не «по 5% от входа». Расчёт через ATR.
- **Take-profit 1/2/3:** на основе ближайшего сопротивления / измеренного движения / Fibonacci 1.272/1.618.
- **R:R ≥ 2:** если меньше, сделку не открывают.

**Артефакт:** `03-technical.md` с таблицей уровней + скриншот / описание графика.

**Гейт:** есть план «вход — стоп — цель — инвалидация» с числами → Фаза 4.

### Фаза 4. Sentiment, macro, regulatory

Внешний слой, который ломает даже самый красивый DCF.

#### 4.1 Новости и события

- [ ] Свежие 30–60 дней: гайденс, M&A, отчёт, downgrade/upgrade от sell-side.
- [ ] Earnings calendar: дата ближайшего отчёта — открывать позицию через DCF за 3 дня до отчёта = ставить на сюрприз, это другой тип сделки.
- [ ] Конференции, investor days.

#### 4.2 Sentiment indicators

- [ ] **Short interest** и days-to-cover — высокий short → squeeze risk или фундаментальная проблема.
- [ ] **Put/Call ratio**, options open interest на ключевых страйках.
- [ ] **Analyst consensus**: средний target, разброс, % buy/hold/sell.
- [ ] **Insider transactions** — последние 6 месяцев; крупные продажи топ-менеджмента или совета — флаг.
- [ ] **Institutional ownership** изменения (13F).
- [ ] **Social/news sentiment**: NLP-метрики, если доступны (Twitter/X, Reddit, новостные API). С осторожностью — данные шумные.

#### 4.3 Макро

- [ ] Чувствительность к ставкам ФРС / ЦБ.
- [ ] Чувствительность к курсу (валютная пара выручка/затраты).
- [ ] Цикл сырья (для commodity-зависимых).
- [ ] Инфляция, потребительский спрос (CPI, retail sales).

#### 4.4 Regulatory & ESG

- [ ] Открытые расследования, антимонопольные дела, налоговые претензии.
- [ ] Санкции / экспортный контроль.
- [ ] Климатические и социальные риски (для industries-чувствительных).

**Артефакт:** `04-sentiment.md`.

**Гейт:** есть список **триггеров** (что должно случиться, чтобы тезис подтвердился или сломался) с привязкой к датам → Фаза 5.

### Фаза 5. Synthesis (bull / bear / base)

Здесь агент **обязан** сформулировать ВСЕ три сценария — это не косметика.

Для каждого сценария:

| Поле | Что |
|---|---|
| Предпосылки | 3–5 ключевых допущений |
| Драйверы | что должно произойти |
| Целевая цена | по тому же методу, что в фазе 2 |
| Вероятность | субъективная, но обоснованная (например, 25 / 50 / 25) |
| Что увижу первым | leading indicator подтверждения |
| Что сломает | leading indicator опровержения |

Базовая оценка через E(price) = Σ P_i × Target_i, далее сравнение с текущей ценой.

**Risk register** — отдельная таблица:

- риск → вероятность → impact → митигация → kill switch (условие выхода).

**Чувствительность:** табличка ключевых параметров (revenue growth, margin, WACC, multiple expansion) → fair value. Видно, где модель «хрупкая».

**Артефакт:** `05-synthesis.md`.

**Гейт:** три сценария готовы, vероятности нормированы (Σ = 100%), риски с kill switches → Фаза 6.

### Фаза 6. Verdict & action plan

Финальный документ, который пользователь читает один.

Структура одностраничника:

1. **TL;DR (3 строки):** тикер, рекомендация, цель/срок.
2. **Тезис (5–7 строк):** почему именно сейчас, чем компания отличается.
3. **Анти-тезис (3–5 строк):** что говорит «нет», и почему агент не согласен.
4. **План действия:**
   - Размер позиции (Kelly fraction × коэффициент осторожности, либо фиксированный % портфеля).
   - Точка входа (диапазон, тип ордера).
   - Стоп-лосс (число + триггер: цена / новость / отчёт).
   - Тейк-профиты: TP1 / TP2 / TP3 с долями фиксации.
   - Горизонт пересмотра тезиса (когда следующий обязательный review).
5. **Мониторинг:** список метрик и событий с пороговыми значениями, при которых тезис пересматривается.
6. **Disclaimer:** «не индивидуальная инвестиционная рекомендация» — обязательно.

**Артефакт:** `06-verdict.md`.

**Гейт:** документ подписан агентом, прошёл self-review (см. §5).

## 5. Self-review (как в superpowers)

После каждого артефакта и перед финальным verdict — агент проходит чек-лист «свежими глазами» (по аналогии со Spec Self-Review в brainstorming-скилле):

1. **Placeholder scan.** В тексте остались «TBD», «TODO», прочерки? → исправить.
2. **Internal consistency.** Не противоречат ли DCF (фаза 2) и сценарии (фаза 5)? Совпадают ли target price в одностраничнике и в DCF? Совпадают ли уровни TA и тайминг тезиса?
3. **Scope check.** Не пытается ли агент дать прогноз за пределами scope из фазы 0 (например, горизонт был 1 год, а тезис — про «10 лет вперёд»)?
4. **Ambiguity.** Каждое числовое утверждение имеет единицу измерения, валюту, период? «Маржа 12%» — gross/operating/net?
5. **Evidence audit.** Все ли утверждения помечены либо источником, либо `[hypothesis]`?
6. **Anti-pattern audit** (см. §6).

## 6. Anti-patterns и когнитивные искажения

Каталог типовых ошибок и как агент должен их ловить.

| Паттерн | Симптом | Контрприём |
|---|---|---|
| **Anchoring** | «Год назад акция стоила $200, значит $130 — дёшево» | Сравнивать с fair value, не с историей цены |
| **Confirmation bias** | Игнор информации против тезиса | Обязательный bear case с конкретикой |
| **Recency bias** | Экстраполяция последнего квартала на 10 лет | Минимум 5y, лучше 10y данных в фундаментале |
| **Survivorship** | «Компании сектора растут по 20%» (без учёта закрывшихся) | Использовать индексы / equally-weighted peer median |
| **Narrative fallacy** | Красивая история без чисел | YAGNI к нарративам без подтверждения в P&L/CF |
| **Curve fitting в TA** | «Идеальный треугольник» на 3 точках | Минимум 4 касания, объём подтверждает |
| **Over-precision** | «Target $147.83» | Возвращать диапазон ($140–$160), центральное значение |
| **Single-method valuation** | Только DCF или только мультипликаторы | Минимум 2 метода, расхождение объясняется |
| **Ignoring base rates** | «У компании отличный шанс выйти в новый рынок» — без статистики, сколько вообще такое получается | Base rate из истории сектора |
| **Vibe investing** | Финальный тезис без артефактов фаз 0–5 | HARD-GATE |
| **Hindsight in backtest** | «На таких уровнях акция всегда отскакивала» — на 3 случаях | Требовать N ≥ 10 или явно помечать как weak evidence |
| **Author bias** | Брать sell-side target как факт | Sell-side — это input, не вывод |

## 8. Применение в текущем репозитории (локальный Ollama)

Этот репозиторий — стек локальной LLM на Ollama (Qwen2.5 14B / Mistral Nemo 12B). Финансовый агент собирается аналогично существующим Modelfile-ам:

1. **Modelfile** `modelfiles/finance-agent.Modelfile` — наследует Qwen2.5 14B, в `SYSTEM` кладётся корневой системный промпт (см. §4.1) с указанием путей к skills.
2. **Skills** в `.claude/skills/financial-analysis/` (если работа идёт через Claude Code) либо вклеиваются в один большой системный промпт для Ollama.
3. **Python-обвязка** — по аналогии с `translate/translate_book.py`: скрипт, который ведёт пользователя по фазам, дёргает Ollama API, сохраняет артефакты в `docs/research/<TICKER>/<YYYY-MM-DD>/`. Под отдельный шаг — Python-инструменты (`yfinance`, `pandas-ta`) как «tool calls» через формат, который понимает Qwen.

**Ограничение.** Ollama-инсталляция офлайновая, поэтому **web search не работает из коробки**. Решения:

- запускать агент с MCP web-search сервером (если используется Claude Code или совместимый рантайм);
- либо для локального Qwen — на фазах 1 и 4 явно просить пользователя приложить свежие новости / отчёт (агент тогда работает в режиме «human as web»).

Без этого выход агента нужно помечать как `cutoff: <model_knowledge_date>` и предупреждать о риске устаревших данных.

## 9. Метрики качества работы агента

Чтобы понимать, что workflow приносит пользу:

- **Coverage:** доля артефактов фаз 0–6, реально сохранённых на диске. Цель — 100%.
- **Disagreement-explained rate:** доля расхождений между методами оценки (DCF vs multiples, base vs bull) с явным объяснением. Цель — 100%.
- **Anti-pattern hits:** число пойманных при self-review (§5) проблем за анализ. Если стабильно 0 — self-review не работает; если > 5 — сам процесс генерации сырой.
- **Calibration:** через 3–6 месяцев сверять, где оказалась цена vs три сценария. Если bear/base/bull попадают в свои интервалы пропорционально заявленным вероятностям — калибровка ок.
- **Time to verdict:** от scope до тезиса — для одного аналитика-агента ~ 2–4 часа интерактивной работы. Меньше часа — скорее всего пропущены фазы.
